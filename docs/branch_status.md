# Branch status

**`rate-coherence` is the live development line.** Every result, finding,
and chapter draft in this repository traces to it, not to `main`.

## `main` is stale

`main` is at `1de9fc6` (2026-08-21). It predates the rate-coherence
correction, the A5 builder port, and everything else committed since.
**Do not use `main` as the basis for any result, figure, or citation.**
If a script, a notebook, or a reader's checkout is on `main`, it is
running against pre-correction code.

## Commit count ahead of `main`

As of this commit, `rate-coherence` is **142 commits ahead of `main`**
(`git rev-list --count main..rate-coherence`). This number moves with
every commit on this branch — re-run that command for the live count
rather than trusting this file to stay current between sessions. It is
recorded here as a snapshot at the moment this file was written, not as
a maintained counter.

## `pre-phase-b` tag

An annotated tag `pre-phase-b` marks the state of the branch immediately
before Phase B's ~3,000-solve re-run begins. Per this task's own commit
order (`TASK.md`, "Scope," item 5), the tag is created **after** this
file is committed, on the resulting HEAD — which means this file cannot
state the tag's SHA as a fact already true at the moment of its own
commit (the tag's target is this very commit, and a commit's hash is a
function of its own content; a file cannot correctly state its own
commit's hash in advance without that hash already being wrong). Rather
than write a value that would be stale or fabricated, resolve it
directly:

```
git rev-parse pre-phase-b
```

The authoritative record of what SHA the tag resolved to, confirmed
after the fact, is `docs/task_log_00_branch_provenance.md` (this task's
own report) — written last, after the tag exists, so it can state the
concrete value rather than a forward reference.

## Results provenance

`results/` is gitignored (`.gitignore:6`), with five pre-existing
tracked exceptions under `results/_sdr_sweep_v3/` (tracked before the
ignore rule was added; `.gitignore` does not retroactively untrack a
file). The pre-Phase-B snapshot (`results_pre_phase_b/`, a straight copy
of `results/` at the `pre-phase-b` tag) mirrors that treatment — it is
**not** tracked, and `.gitignore` was extended with a `results_pre_phase_b/`
entry for exactly that reason, so its ~2,168 files do not appear as
untracked noise in `git status`. The snapshot's own provenance value is
therefore entirely in the manifest, not in git history:
`docs/results_manifest_pre_phase_b.md` records every file's SHA-256,
byte size, and modification time, generated by
`scripts/make_results_manifest.py`, which takes a results root and an
output path and can be re-run after Phase B against the same `results/`
root to produce a second manifest for diffing.
